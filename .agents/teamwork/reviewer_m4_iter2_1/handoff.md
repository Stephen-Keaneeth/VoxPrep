  ```python
  for cls, args, kwargs in reversed(middleware):

  ```
  Resulting stack onion (outermost to innermost):

## 2. Logic Chain

1. **Root Cause Analysis Confirmed**:
   In Milestone 4 Iteration 1, `CORSMiddleware` was registered first, causing `GlobalExceptionMiddleware` (registered second) to be prepended by Starlette's `self.user_middleware.insert(0, ...)` and sit outermost. When an unhandled exception occurred, `GlobalExceptionMiddleware` intercepted it and sent a 500 `JSONResponse` directly, bypassing `CORSMiddleware`.
2. **Correctness of Ordering Reversal**:
   By adding `GlobalExceptionMiddleware` first and `CORSMiddleware` second, `CORSMiddleware` is inserted at index 0 of `user_middleware`. In `build_middleware_stack`, the stack becomes `CORSMiddleware(GlobalExceptionMiddleware(ExceptionMiddleware(router)))`. On all responses—including HTTP 500 responses emitted by `GlobalExceptionMiddleware`—the response flows through `CORSMiddleware.send`, ensuring CORS headers are added.
3. **Defense-in-Depth Layering**:
   Even if an exception were to bypass `CORSMiddleware` or outer layers, `GlobalExceptionMiddleware` extracts the `Origin` header directly from `scope["headers"]` and attaches `Access-Control-Allow-Origin: <origin>`, `Access-Control-Allow-Credentials: true`, and `Vary: Origin` directly to the `JSONResponse`. Starlette's `MutableHeaders` replaces existing single-value headers cleanly without duplicate keys.
4. **CORS Coverage Across All Status Codes**:
   - HTTP 200: Handled by router -> passes through `CORSMiddleware` (Verified via `test_health.py` and `test_tier1_features.py`).
   - HTTP 400: Handled by `http_exception_handler` -> passes through `CORSMiddleware` (Verified via `test_adversarial_errors.py`).
   - HTTP 401: Handled by `http_exception_handler` -> passes through `CORSMiddleware` (Verified via `test_adversarial_auth.py`).
   - HTTP 404: Handled by `http_exception_handler` -> passes through `CORSMiddleware` (Verified via `test_adversarial_errors.py`).
   - HTTP 422: Handled by `validation_exception_handler` -> passes through `CORSMiddleware` (Verified via `test_adversarial_errors.py`).
   - HTTP 500: Handled by `GlobalExceptionMiddleware` + `generic_exception_handler` -> passes through `CORSMiddleware` (Verified via `test_errors.py` and `test_adversarial_errors.py`).
5. **Deployment Parity**:
   `railway.json` points to `"dockerfilePath": "Dockerfile"` and `"startCommand": "uvicorn app.main:app --host 0.0.0.0 --port $PORT"`, resolving the monorepo path mismatch with container `/app`.

## 3. Adversarial Challenges & Caveats

### Challenge 1 (Minor Finding / Caveat): Direct Origin Reflection on 500 Bypasses Origin Whitelist
- **Observation**: In `GlobalExceptionMiddleware.__call__` (lines 87–101), any incoming `Origin` header value is reflected on 500 responses without checking whether it is present in `get_allowed_origins()`.
- **Attack Scenario**: If `ALLOWED_ORIGINS="https://trusted.client.com"` is configured, an untrusted origin `https://attacker.site` triggering an unhandled 500 error will receive `Access-Control-Allow-Origin: https://attacker.site`.
- **Blast Radius**: Minimal / Low. The 500 response body is strictly sanitized (`{"detail": "Internal server error occurred.", "error_type": "internal_server_error", "status_code": 500}`) and contains no sensitive credentials, stack traces, or session state. Browser fetch clients benefit from receiving valid CORS headers so error alerts can render rather than triggering opaque network failures.
- **Mitigation Recommendation (Future Hardening)**: For high-security environments, `GlobalExceptionMiddleware` can compare `origin` against `get_allowed_origins()` before reflecting. For the current hackathon MVP, the current behavior safely prevents browser CORS blockage on unexpected crashes.

### Challenge 2: Streaming / Partial Responses on Error
- **Observation**: If an exception occurs after `http.response.start` has been sent (e.g., during chunked streaming), `GlobalExceptionMiddleware` correctly guards `if not response_started:`, avoiding illegal duplicate `http.response.start` ASGI messages.
- **Result**: Robust and compliant with the ASGI 3.0 specification.
